## Live production bugs found and fixed

- **Company Dashboard crashed for every employer** (#168). `0ec48204` (Nov 5) switched `CompanyJobsList` to the shared `SortableTable` without importing it, so `/company-dashboard` rendered the error boundary ("SortableTable is not defined").
- **Stripe jobs frozen since Oct 9** (#177, #180). #149 turned Stripe's placeholder locations ("LOCATION", "N/A") into `undefined`; `jobs.location` is NOT NULL; one bad row failed the whole 764-row upsert on every run. No new Stripe postings, no closed ones removed, for four weeks, while the Migrate Jobs action reported **success** every time. Fixes in `scripts/migrateJobs.ts`:
  - a missing location becomes "Location not specified" (covers every adapter);
  - any failed source makes the run exit non-zero, so the action goes red;
  - upserts are batched by 250. The first post-fix run caught Equinox hitting a statement timeout (57014) on one 758-row upsert.

  After the fix: Stripe 766 saved, 222 stale removed; all six sources green.
- **Test companies on the live homepage** (#175). "Trusted by companies of all sizes" took whichever companies owned the first 16 job rows, which surfaced seed accounts (DesignCo, TechCorp, a duplicate "Quadrant Inc"). Now **"Open IT roles at"**: employers ranked by open IT roles (min 3), name variants merged, tiles link to that company's jobs. Wording is deliberately not "hiring on Nexegin": Palantir/Stripe/Grab/Notion jobs are imported from their public careers boards (#142); they don't post here.
- **Homepage sections duplicated each other** (#175). "Trending Now" was the first 9 rows of an unordered query, and "Recommended For You" scored those same ~10 jobs. Now:
  - the job list is newest-first with an id tie-break (pagination no longer reshuffles), titled "Latest IT jobs" or "Jobs matching your search";
  - recommendations score the 100 newest IT jobs, fetched only for users with saved/viewed history, and exclude anything already listed.
